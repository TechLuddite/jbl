# CLAUDE.md — Joseph's Battle Lab

## What this is

A Pokémon battle calculator, stat explorer, and family league tracker. It is a
birthday present for a 12-year-old who likes numbers. That audience drives every
decision below.

Live at **https://jbl.opsvibe.systems** · repo `TechLuddite/jbl`

## The one rule that matters

**`src/lib/battle.js` is the reference implementation and it is correct.**

It is covered by `src/lib/battle.test.js`, whose expected values were derived by
hand from the published formulas. If a test fails after your change:

- Your change is wrong. Fix the code.
- **Do not** edit the expected values to match your output.
- **Do not** delete or skip the test.

Two things in that file are counter-intuitive and get "corrected" into being
wrong by people who half-remember the formulas:

1. **Flooring happens mid-formula, not once at the end.** The truncation points
   are load-bearing.
2. **In Gen 5+, the random 85–100% roll is applied BEFORE STAB and type
   effectiveness.** Not after. Reordering shifts results by a few points.

Same applies to `src/lib/typeChart.js`. It is a lookup table. Every entry is
deliberate. Ground does not resist Fire; Steel no longer resists Ghost or Dark
(that changed in Gen 6). Do not refactor it into something "cleverer".

## Commands

```bash
npm install        # once
npm run dev        # local dev server
npm run test       # vitest, watch mode
npm run test:run   # single run — what CI uses
npm run build      # production build into dist/
npm run preview    # serve the built output
npm run refresh-dex  # re-bake the full dex from PokéAPI (~5-10 min)
npm run refresh-flags # re-bake move flags (contact, punch, sound...)
npm run refresh-species # re-bake the Pokédex details: bios, sizes, evolutions,
                        # ability text (~5-10 min; LIMIT=20 for a quick check)
```

Before you say you're finished: `npm run test:run && npm run build`. Both must
be green. CI runs exactly these and a red result blocks the deploy.

## Hard constraints

**Move flags are baked, not guessed.** PokéAPI's move endpoint has no flags
block at all, and whether a move makes CONTACT decides Static, Flame Body,
Rough Skin, Iron Barbs, Rocky Helmet, Tough Claws and the punish riders on
Spiky Shield and King's Shield. `npm run refresh-flags` fetches them from
Pokémon Showdown's published data and writes `src/data/move-flags.json`, which
`data/index.js` attaches to every move object. Same rules as the dex: bake
manually, commit the JSON, never fetch at runtime. `move-flags.test.js` guards
against a bake that quietly produces an empty file — that failure mode would
switch Static off without anything else complaining.

**A version-group id is not a date.** `scripts/version-groups.mjs` decides which
game a learnset comes from, and both bakes share it so a move's level and the
learnset it sits in always agree. It exists because ranking PokéAPI's version
groups by id — the obvious thing — is wrong twice over: the Japan-only Gen 1
re-releases were added to the API years late and carry ids *above*
Scarlet/Violet, and the Legends games and battle-only spin-offs rebuilt moves
from scratch, so a Zubat in Legends: Arceus knows seven moves and there are no
TMs at all. Left alone, that stranded 187 Pokémon on their Red/Blue movesets.
A new main-series game needs nothing doing; a new spin-off needs a line in that
file, or half the dex quietly forgets how to battle.

**The Pokédex bio is a quotation, not a description.** `species.json` stores the
flavour text verbatim from the games *and* which game it came from, and the tab
prints the attribution under it. That is the only reason it is safe to show:
nothing on that page is something we wrote about a Pokémon. If you add a field
there, it holds either a number out of the dex or the game's own words. Don't
summarise, don't paraphrase, don't fill a gap with something plausible.
`species.test.js` guards the bake, including the "every bio names its game"
rule.

**Never call PokéAPI at runtime.** It is free but explicitly asks consumers to
cache locally, and 1300 sequential fetches is unusable on a phone. Run
`npm run refresh-dex` once, commit the JSON, ship it static. This also makes the
app work offline, which is most of its real-world use (car journeys).

**`base` in `vite.config.js` must stay `"/"`.** The site is served from the
custom domain `jbl.opsvibe.systems`, which serves from the root. It would only
become `"/jbl/"` if the custom domain were dropped in favour of
`techluddite.github.io/jbl`.

**`public/CNAME` must survive into `dist/`.** Without it, GitHub Pages drops the
custom domain on every deploy. The workflow asserts this explicitly — leave that
check in.

**No new dependencies without asking.** The stack is React + Vite + Vitest and
that is enough. This is a small app that should still build in three years.

## Style

- Plain CSS in `styles.css` using the CSS custom properties at the top. No
  Tailwind, no CSS-in-JS. Inline `style` is fine for dynamic values (bar widths,
  type colours) and nothing else.
- Function components and hooks. No class components.
- Comments explain *why*, not *what*. The math files earn long comments; the UI
  files mostly do not.
- Copy is written for a 12-year-old: plain verbs, no jargon, sentence case.
  "Record result", not "Submit battle entry".

## Design intent

The visual direction is **a handheld Pokédex device**: red moulded shell with
inset shadows, a green-tinted LCD panel, data set in IBM Plex Mono because it's
a device readout. Headings are Archivo.

The signature element is the **16-roll damage strip** in the calculator. It
exists to teach one idea: damage is not a number, it's a range of sixteen
possible numbers. Do not replace it with a single averaged figure. Do not
collapse the "showing the work" steps into a summary. The working-out *is* the
product.

## Deliberate v1 limitations

Do not "fix" these without being asked — they're tracked in ROADMAP.md:

- League data is localStorage, single-device. Export/import JSON is the stopgap.
- The tourney is single-elimination only; no round-robin, seasons or badges.

## The battle sim (in progress)

Scope was agreed in 2026-08 and lives in ROADMAP.md. The short version:
two u-pick teams of 1–6, hotseat and auto modes, real learnsets from the
latest version group, and an engine that grows toward statuses, stat stages,
weather, hazards, items and abilities — items/abilities as a curated set
first. `src/lib/sim.js` follows the same law as `battle.js`: every mechanic
tested with hand-derived values, RNG injected so tests are exact, and the
existing battle.js/typeChart.js files stay untouched.

The item and ability sets grew a long way in 2026-08 — 11 items to ~75 and 25
abilities to ~130 — after Joseph pointed out that most Pokémon had an ability
the sim had never heard of. The rule did not change: **modeled and hand-tested,
or not offered.** Two things there are worth knowing before adding more:

- **`seenAbility(attacker, defender)` is how anything reads the DEFENDER's
  ability**, so Mold Breaker can switch it off. Abilities that punish a move
  *after* it lands — Static, Rough Skin, Aftermath — deliberately read
  `foe.ability` directly, because Mold Breaker doesn't stop those.
- **Abilities that genuinely do nothing in a one-on-one battle** (Pickup, Run
  Away, Telepathy, the doubles-only ones) are listed with `noop: true` and
  grouped as such. That is an honest entry, not a stub — don't "implement"
  them, and don't delete them either, or those Pokémon look broken again.

Everything that spans more than one turn landed in 2026-08: charge moves,
recharge, rampage locks, confusion, trapping, Leech Seed, Wish, Future Sight,
Perish Song, Yawn, Taunt/Encore/Disable, screens, Tailwind, Trick Room,
Protect and Substitute. Two rules there are easy to "fix" into being wrong:

- **Every counter ticks in one place, `endOfTurn`, in the order written at the
  top of that function.** A Pokémon on 4 HP with a burn and a Wish incoming
  lives or dies on that order. Don't reshuffle it to read more nicely.
- **PokéAPI's `damage-raise` meta category means "damage, then change the
  USER's stats" — even when the change is a drop.** That is why Draco Meteor
  and Close Combat sit in the same bucket as Meteor Mash. `damage-lower` is
  the one that points at the target. Reading the sign of the stat change
  instead sends Power-Up Punch's boost to the opponent.

Status moves ignore type immunity (Encore works on a Ghost), except Electric
and Poison ones. That is deliberate and matches the games; the type chart
gate is for attacks. On the Battle tab, sim
results only enter the league when the player says yes to the post-battle
prompt; battles started from the League tab (one-off matches and tourney
rounds) are league events by nature and record automatically.

## The changelog is part of shipping

**Any change a player would notice gets an entry in `src/data/changelog.js`,
in the same commit.** The top entry's date is also the version stamp attached
to every bug report, so a stale changelog means every report that follows is
mislabelled.

Write it for the person using the app, not for a developer: what it means in a
battle, not what changed in the code. Use `credit` when someone reported it —
being named in the changelog is the best part of reporting something.

Reports themselves have no backend and never will: `Report.jsx` composes the
text, `lib/feedback.js` turns it into a pre-filled GitHub issue URL, and the
reporter presses submit on GitHub. Nothing about the user is collected.

## Working style

- Small, focused commits. Conventional commit messages (`feat:`, `fix:`,
  `docs:`, `chore:`).
- When adding a feature to the calculator, add a test to `battle.test.js` first
  if it touches the math.
- If a request conflicts with something in this file, say so before proceeding
  rather than silently picking one.
